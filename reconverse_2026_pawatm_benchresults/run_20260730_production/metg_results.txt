Task Bench: minimum effective task granularity (METG)
==============================================================================

Machine      : NCSA Delta CPU node, 2x AMD EPYC 7763 (64 cores each), 1 node
Dependence   : stencil_1d
Kernel       : compute_bound
Time steps   : 1000
Graph width  : equal to the PE count
Granularity  : swept with -iter, halving from 16384 down to 2
PE placement : MPI uses one rank per PE; Charm++, Converse and Reconverse
               put all PEs in a single process

time_per_task = elapsed / total_tasks * cores * 1000   [ms]

efficiency (the METG curve) is measured against each system's OWN
coarsest-granularity run, as task-bench's chart_metg.py does when no
hardware peak is supplied:

    scale_factor = iter_coarsest / iter
    efficiency   = elapsed_coarsest / (elapsed * scale_factor)

At the coarsest point a task is 55-75 ms and the runtime's own overhead
is microseconds, so that point is that system running essentially
overhead-free.  Normalising there isolates what METG is meant to
measure -- how small a task the runtime can still keep cores busy on --
and cancels the node's clock-state variation, which moves a system's
coarse and fine points together.

'vs peak' is the secondary, absolute view: achieved FLOP/s over the
kernel_bench hardware peak for that core count.  It can exceed 100%
when a run catches the boosted clock state that kernel_bench, which
pins worker i to core i, does not reach on cores 1..n-1.

Hardware peak per core count (task-bench kernel_bench: the same kernel in
a bare pinned-pthread loop, no runtime underneath), used for 'vs peak':

 cores      peak FLOP/s       spread     reps
     1     3.801677e+10         0.2%       15
     2     6.082986e+10         0.2%       15
     4     1.216553e+11         0.2%       15
     8     2.431858e+11         0.2%       15

Statistic: every point below is the MEDIAN of 5 repetitions.

These nodes intermittently drop to a lower sustained clock, costing
about 25-33% on identical work; the effect is bimodal rather than
gaussian, so a mean is pulled around by however many slow repetitions a
configuration happened to catch, and a best-of rewards whichever system
got lucky.  The median rejects up to two contaminated repetitions out
of five.  The 'spread' column is (worst-best)/best, so it shows how
much each point was affected.

The sweep itself interleaves all five systems at every measurement point
and rotates which one goes first on each repetition.  Running each
system's sweep as a contiguous block -- as done initially -- gave
whichever system ran first a systematically cooler node and biased the
comparison by ~25%.
