User-level thread (ULT) benchmarks: Reconverse vs original Converse
==============================================================================

Machine : NCSA Delta CPU node, 2x AMD EPYC 7763 (64 cores each), 1 node
Source  : reconverse/tests/ult_bench (sched_rate.cpp, ctxswitch.cpp).
          The same sources build against both layers; the Converse build
          differs only in ConverseInit's argument count (see
          /u/rao1/ult_bench_converse/converse_compat.h), so the measured
          code paths are identical.
Threads : Converse uses the Charm++ build's default ULT implementation
          (generic64-light assembly threads); Reconverse uses its
          boost-context based threads.
Numbers : each PE reports its own best-of-repetitions figure; the tables
          show the mean across PEs.  Lower is better throughout.

Caveat  : in the sched_rate sweep both layers speed up at the largest
          thread counts (>=512).  That is a property of the benchmark --
          more runnable ULTs amortise the fixed per-repetition costs --
          not of either runtime, and it shows up equally in both, so the
          Converse/Reconverse ratio is the meaningful column.

Control: does the Converse result depend on its ULT implementation?
------------------------------------------------------------------------------
Charm++ can build Converse threads several ways (charmc -thread ...).  A
reasonable objection to the comparison above is that it pits Reconverse's
boost-context threads against whichever one Charm happened to default to.
So the same benchmarks were rebuilt against each, on 1 PE.

-thread              sched_rate ctxswitch direct  ctxswitch sched
                    us/dispatch    us/switch @64    us/switch @64
default (qt)             0.1767           0.0620           0.2408
context                  0.8794           0.3974           0.8729
pthreads       did not complete                -                -

The build default -- generic64-light assembly threads -- is already the
fastest option available to Converse, by roughly 5-7x over ucontext.  The
Reconverse advantage in the tables above is therefore measured against
Converse's best case, not an unfavourable build choice.

(-thread pthreads did not finish 200000 switches and was dropped; it maps
ULTs onto kernel threads, so it is not a comparable ULT implementation.)
